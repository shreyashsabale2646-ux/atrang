## 3. Quick Start & Execution Guide

### 3.1 Start Database (PostgreSQL)

You can run PostgreSQL via Docker Compose:
```bash
docker compose up -d postgres
```
*Or using local Homebrew PostgreSQL:*
```bash
brew services start postgresql@18
createdb atrang
createuser -s atrang_app
```

### 3.2 Start Java Spring Boot Backend
Requires JDK 21 and Maven 3.9+:
```bash
cd backend
export JAVA_HOME=/opt/homebrew/opt/openjdk@21   # adjust to your JDK 21 path
export PATH=$JAVA_HOME/bin:$PATH

# Run tests
mvn test

# Start the Spring Boot application
mvn spring-boot:run
```
The REST API starts on `http://localhost:8080`. Flyway automatically creates and migrates all 5 relational tables, views, triggers, and sample data.

### 3.3 Start Next.js Frontend
Requires Node.js 20.9+:
```bash
npm install
npm run dev
```
Open `http://localhost:3000` in your browser.

## 5. Relational Database Design (3NF)

### 5.1 Relational Tables
1. **`admin_users`** — Administrative credentials, roles (`ROLE_ADMIN`, `ROLE_SUPERADMIN`), active status, timestamps.
2. **`event_categories`** — Minecraft biomes / technical fest domains (Code, Name, Description, Hex Color, Display Order).
3. **`events`** — Core festival events linked to `event_categories(id)` via Foreign Key (`ON DELETE RESTRICT`). Stores format, venue, prizes, and publication status.
4. **`event_sessions`** — Detailed timetable slots linked to `events(id)` via Foreign Key (`ON DELETE CASCADE`).
5. **`event_audit_logs`** — Automated security audit trail generated by PostgreSQL triggers (`ON DELETE SET NULL`).

### 5.2 Advanced Database Objects
- **Database View `v_event_details`:** 3-table relational JOIN aggregating session counts for fast, consistent catalog queries.
- **Database View `v_category_metrics`:** Analytical aggregate view calculating total events, published counts, draft counts, and session totals per domain using `GROUP BY`.
- **Trigger `trg_events_audit_log`:** PL/pgSQL trigger executing `fn_audit_event_mutation()` `AFTER INSERT OR UPDATE OR DELETE ON events` to log all mutations.
- **Trigger `trg_update_timestamp`:** Automatically updates `updated_at` before row modifications.
- **Stored Function `fn_get_fest_stats()`:** Returns system-wide festival metrics in a single query.
